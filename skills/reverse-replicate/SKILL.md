# 逆向复刻：把好东西拆开，做成自己的一套

适用：用户看到一个好用的网站/软件/游戏、一个好想法、一个厉害的人或一本好书，想“搞清楚它为什么好、怎么做到的，然后自己有一套”。
核心原则：**复刻的是“行为和价值”，不是“代码和外壳”。** 先找清楚“魔法在哪”，拿得到就学，拿不到就按功能清单 + 输入输出样例自己实现，能用成熟开源件的就别自己写。
最后交付的永远是两样：**一份复刻方案（报告）+ 一个能用的东西**（本地程序、脚本、模板、清单、提示词、行动计划，按对象而定）。

---

## 0. 定目标（不超过 3 个问题，能默认就默认）

1. **复刻什么**：整体，还是最打动你的 1–3 个点？（默认：核心功能 / 核心价值）
2. **给谁用、在哪跑**：自己用还是给客户；跑在 Mac、VPS 还是只要一份文档？（默认：自己用，先本地跑通，要常驻再上 VPS）
3. **做到什么程度**：能用就行 / 要接近原版体验 / 要比原版好在哪？

用一句话写下“复刻目标”，后面每一步都对照它。

## 1. 判断类型，选侦察手段

| 类型 | 要搞清楚的 | 侦察手段 |
|---|---|---|
| 网站 / Web 应用 | 功能清单、支持范围、输入输出、前后端分界、接口、技术栈 | REA 静态分析前端；无头浏览器抓网络请求（patchright/Playwright）；看 JS bundle、sitemap、robots、响应头；Tavily extract 读页面 |
| 桌面 / 移动软件 | 功能、交互流程、数据格式、依赖 | 官方文档、更新日志、用户评论；REA（Electron/JS/.NET/原生二进制，需本机工具，仅限自己有权分析的软件） |
| 游戏 | 核心循环、规则和数值、关卡/成长、手感、美术风格、变现 | 实机视频逐镜头拆（抽帧/切镜头）、Wiki 和攻略、玩家评论；先做最小可玩原型 |
| 想法 / 商业模式 / 产品 | 解决谁的什么问题、为什么现在、怎么赚钱、获客渠道、护城河 | 官网和定价页、Reddit/评论/应用商店评分（可配合 staged-market-scrape）、Google Trends、竞品 |
| 人（公开人物） | 原则、思维模型、决策规则、做事流程、习惯、表达风格 | 只用公开资料：著作、访谈、演讲、文章、公开言论；按“说过什么→怎么做事→为什么”整理 |
| 书 | 核心论点、框架、方法步骤、练习、反例 | 目录结构、各章要点、书中自带的工具；把方法变成清单/模板/日程 |

**网站/软件优先用 REA**（github.com/morluto/rea，“Reverse Engineer Anything”）：
- 装到 Claude Code：`npx rea-agents setup`（会改 agent 配置，先告诉用户）；只想一次性用：
  `npx -y rea-agents@latest analyze-javascript-application /abs/path/to/app --json`
- 网站：先把页面和 JS 存到本地目录（浏览器保存或抓包），再对该目录跑分析；原生二进制需要 Hopper/Ghidra/IDA。
- 拿不到 REA 时，用无头浏览器 + 读 JS 也能做同样的判断，不要卡在工具上。

## 2. 找“魔法在哪”（最关键的一步）

逐个核心功能回答：**实现它的关键逻辑，在我拿得到的地方吗？**

- **拿得到**（前端代码、公开 API、开源依赖、书里写明的方法、人公开讲过的原则）→ 学它的做法，用自己的代码/语言重写。
- **拿不到**（在对方服务器、付费墙后、私有数据、人没公开的部分）→ **不硬拆**。改为“行为复刻”：
  1. 列功能清单和支持范围（例：支持哪 9 个平台、识别哪些链接格式）；
  2. 收集 5–20 组真实输入输出样例当“验收样本”；
  3. 自己实现，或找能做到同样输出的开源方案。
- 写下结论：哪些是“照学”，哪些是“行为复刻”，哪些复刻不了（及原因）。

> 例：dyxhsdownloader.com 用 REA 一看，前端只是把链接交给自家服务器 `/api/parse`，还隔着 Cloudflare 人机验证，去水印逻辑在服务端 → 改为按它的平台清单和链接规则在本地自己解析，主力平台自研，其余交给 yt-dlp 兜底。

## 3. 写复刻规格（Spec）

- **功能清单**：P0（不做就没意义）/ P1（体验关键）/ P2（锦上添花）。默认只做 P0 + 少量 P1。
- **输入输出契约**：用户给什么，拿回什么，失败时怎么提示。
- **验收样本**：从第 2 步的样例里挑，写成表格：输入 → 原版结果 → 期望结果。
- **非软件对象**的“规格”：
  - 人 → 原则清单 + 决策规则（“遇到 X 时他会 Y，因为 Z”）+ 可执行的日/周流程 + 一份“用他的方式思考”的提示词；
  - 书 → 方法步骤 + 检查清单 + 模板 + 30 天练习计划；
  - 想法 → 一页商业画布 + 最小可行版本（MVP）的功能和验证指标；
  - 游戏 → 核心循环图 + 数值表 + 最小可玩原型的范围。

## 4. 先借后造

1. 先搜开源同类和成熟组件（GitHub、PyPI/npm、Awesome 列表）。例：视频下载有 yt-dlp，爬虫有 patchright，图表有现成库。
2. 组合方式：**主力场景自己做精，长尾交给成熟开源件兜底。**
3. 注意许可证（MIT/Apache 可直接用；GPL 会传染，用前说明）。

## 5. 做出最小可用版本

- 软件：CLI 先行，再加一个本地网页（只绑 127.0.0.1）。依赖装在项目自己的 venv/node_modules 里。
- 非软件：产出能直接用的东西（清单、模板、提示词、Notion/表格、行动计划），不是读后感。
- 代码放进对应项目仓库，开草稿 PR；密钥放 `.env`（600 权限），不进 git、不进聊天。

## 6. 对照原版实测

- 用验收样本逐条跑，表格列：输入 / 结果（通过、失败）/ 失败原因 / 需要谁做什么。
- 失败要归因：网络/IP（海外 IP 打不开国内站、反之亦然）、要登录 cookies、人机验证、对方接口变了、我们的 bug。只修“我们的 bug”，其余写清楚需要用户提供什么（cookies、代理、账号）。
- 中国平台在国内网络测（例：在用户 Mac 上测），海外平台在美国 IP 测（例：VPS）。
- 能抽检就抽检（例：抽帧确认确实无水印），不要只看“下载成功”。

## 7. 部署（用户要常驻时）

- 本地：给出一行启动命令和访问地址。
- 上 VPS：按服务器规则走（Oliver 的 VPS 见 oliver-vps 技能：常驻服务用 Coolify 部署，新建资源先问，子域名放 oouyang.com，只开 22/80/443）。写好 Dockerfile，在服务器上先构建通过再部署。
- 对外公开前提醒风险：放了用户自己的 cookies/账号的服务，公开等于把账号借给所有人。

## 8. 交付报告

报告（artifact / Claude Doc / 发布页，按所在环境）包含：
1. **一句话结论**：复刻到什么程度，现在能不能用，用户需要做什么。
2. **原版拆解**：它好在哪、核心功能、魔法在哪（证据：截图、请求、代码位置、引用页码）。
3. **复刻方案**：照学的、行为复刻的、复刻不了的及原因；架构或方法图。
4. **实测结果表**。
5. **怎么用**：启动命令 / 链接 / 模板位置。
6. **下一步**：P1/P2 的候选、已知限制、需要用户提供的东西。

## 红线（任何对象都适用）

- 不绕过付费墙、DRM、授权校验、人机验证、登录墙去拿别人的私有内容；需要登录的，用用户自己的账号 cookies，并提醒风险。
- 不照搬对方的品牌、Logo、名字、界面素材和受版权保护的代码/文本/美术；复刻产物要用自己的名字和外观。
- 只分析用户有权分析的软件；不破解、不做盗版、不分发对方的二进制。
- 书：提炼方法和框架，用自己的话写，不大段转录原文；引用标页码。
- 人：只用公开资料，只复刻“做事方法和思维方式”，不冒充本人发言、不伪造他说过的话；不针对普通私人个体。
- 想法/产品：可以学模式，但不抄袭可识别的具体内容，不侵犯商标和专利。

## 按环境调整

**claude.ai 项目 / Claude Code 会话**：用状态清单报进度；代码进仓库开草稿 PR；大任务做完用 artifact 出汇报（Oliver 的偏好）。需要在用户电脑上测，用连接的文件夹/终端工具；要上 VPS，按 oliver-vps 技能。

**VPS 飞书助理（~/work/assistant）**：
- 先用 `bin/todo set` 列 3–6 步计划，每完成一步 `bin/todo done <n>`。
- 只有 `~/work/assistant` 能写：代码和产物放 `outputs/reverse/<项目名>/`；Node 在 PATH 里，可以 `npx -y rea-agents@latest ...`；无头浏览器用 `~/work/scrapers/.venv/bin/python`（patchright）；上网用 WebFetch 或 `tvly extract`（能读到屏蔽 VPS 的站）。
- 视频类素材拆解按 `skills/video-analyze/README.md`。
- 报告默认写 Claude Doc 发链接；网页成果用 `bin/publish`（私有 /r/），文件用 `bin/send-file`。
- 要常驻部署（Coolify）或要 root：Coolify 属于受保护对象，先把 Dockerfile 和方案做好，再请 Oliver 确认，不要自己去碰。
- 抖音/小红书等国内站在 VPS（美国 IP）常打不开，让 Oliver 发文件或在他 Mac 上测。

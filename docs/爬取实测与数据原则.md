# 市场调研数据抓取：实测结果、踩坑记录、不要做原则与质量标准

> 测试时间：2026-10-08（UTC 17:10–17:40）
> 测试环境：Oliver 的 Mac，经本机系统代理（127.0.0.1:7897）出网，出口 IP 显示为 **美国洛杉矶 · AS38136 Akari Networks（机房/代理 IP，非家庭宽带）**。云端容器的网络策略拦截了所有目标站点，所以全部实测在本机完成。
> 所有请求都是只读 GET，间隔 2–8 秒，总量几十次，没有登录任何账号。
> 测试脚本和原始返回在本机 `/tmp/crawl_probe/`（重启后会清掉）。

## 一、一句话结论

| 数据源 | 能不能拿 | 推荐渠道 | 不推荐 |
|---|---|---|---|
| **Reddit** | 能，但必须走授权渠道 | 官方 Data API（OAuth，免费额度 100 次/分钟，非商业）；历史数据用 Arctic Shift 归档 API 做补充 | 未登录直接抓 `.json` / 网页（实测 403） |
| **Google Trends** | 热搜能，关键词曲线很难稳定拿 | 官方 Trends API（alpha，需申请）；小量时手动在网页导出 CSV | pytrends（已归档，实测数据接口约 90% 返回 429） |
| **TikTok** | 公开网页基本拿不到 | 商业用途只能走付费第三方数据商或 TikTok Creative Center 人工看；Research API 只给学术/非营利 | 自己逆向签名接口、批量抓网页（实测拿到空数据，且违反条款） |

**对“做产品前的市场调研”来说，最有价值、最可控的是 Reddit（用户原话和痛点），其次是 Google Trends（需求量级和趋势方向），TikTok 只适合做定性参考。**

## 二、实测记录（有证据的）

### 1. Reddit

| 测试 | 结果 | 说明 |
|---|---|---|
| `www.reddit.com/r/SaaS/top.json`（自定义 UA） | **403**，返回 190KB HTML，页面写着 “blocked by network security” | 未登录 + 机房 IP 直接被拦 |
| 同上，换成 Chrome 浏览器 UA | **403** | 伪装 UA 没用 |
| `old.reddit.com/...json` | **302 跳转到登录页**（`reason=lor2`） | 旧版入口也要求登录 |
| `reddit.com/robots.txt` | `User-agent: * / Disallow: /` | 全站禁止爬虫，并指向 Public Content Policy |
| PullPush 归档 API | **429**：“This website does not provide free scraping resources for agents” | 第三方归档也开始收费/限流 |
| Arctic Shift 归档 API（最新 100 帖） | **200**，可用 | 但见下方数据质量问题 |
| Arctic Shift（8 月底 100 帖 + 100 评论） | 200；偶发 “Timeout. Maybe slow down a bit” 和 SSL 断连 | 需要退避重试 |

**Arctic Shift 数据质量实测（r/SaaS）：**
- 最新 100 帖：抓取时距发帖中位数 **0.01 小时**，所以 **score 全部是 1、评论数中位数是 0**。点赞和评论数是“刚发帖时的快照”，不是最终值。
- 一个月前的 100 帖：都有一次 **36 小时后的二次抓取**（`retrieved_2nd_on`），score 中位数 1、P90 是 6、最高 145。也就是说，指标只更新到发帖后 36 小时。
- **约 39–42% 的帖子被 Reddit 或版主删除**（`removed_by_category`：reddit 22、moderator 16–17）。r/SaaS 这种创业版块里大量是推广/垃圾帖。
- 评论里 14% 已删除，8% 带外链（常见于推广）。
- 同一作者短时间多帖（最新 100 帖里有人发了 4 帖），疑似营销号。

### 2. Google Trends

| 测试 | 结果 |
|---|---|
| 每日热搜 RSS `trends.google.com/trending/rss?geo=US` | **200**，正常返回当天热搜（如 “gemini down”、“gme”） |
| 首页拿 cookie | 200，拿到 `NID` cookie |
| `api/explore`（拿 token，即 pytrends 的第一步） | 连续 6 次 **200** |
| `api/widgetdata/multiline`（真正的曲线数据） | 11 次里 **1 次成功**，其余全是 **429** 或连接中断，每次间隔 8 秒也一样 |
| Python 标准库直连（不带浏览器 cookie 流程） | explore 一步就 **429** |

结论：拿 token 不难，拿数据难。用共享代理 IP 时基本被限流。这跟公开报道一致：pytrends 仓库已于 **2025-04-17 归档**，`interest_over_time()` 首次调用就 429，`trending_searches()` 返回 404。

### 3. TikTok

| 测试 | 结果 |
|---|---|
| `robots.txt` | 对 GPTBot、ClaudeBot、CCBot、Bytespider 等 **全站 Disallow**；对普通 UA 只开放 `/tag`、`/discover`、`/music` 等少数路径 |
| `/tag/skincare` 话题页（浏览器 UA） | **200，360KB**，但服务端渲染数据里**没有任何视频列表或话题统计**，只有 app-context / i18n / a-b 实验配置 |
| 未签名内部接口 `/api/challenge/item_list/` | **200 但 body 为 0 字节** ⚠️ 这是“静默失败” |
| Creative Center 热门话题页 | 跳转到 JS 单页应用，HTML 里没有数据 |
| Research API（不带 token） | 401 `access_token_invalid`，接口存在但需要审批 |

## 三、踩坑清单

1. **“200 OK” 不等于拿到数据。** TikTok 未签名接口返回 200 + 空 body；Reddit 403 页面本身是 190KB 的 HTML。只看状态码或文件大小会误判成功。
2. **代理/机房 IP 是重灾区。** 本机走代理出口是洛杉矶机房 IP，Reddit 直接 403、Google Trends 数据接口 429。换浏览器 UA 也救不回来。
3. **归档数据的点赞/评论数是“早期快照”。** Arctic Shift 在发帖几秒内抓一次、36 小时后再抓一次，之后不更新。用它排“最热帖”会严重失真。
4. **大量内容已被删除。** r/SaaS 近四成帖子被平台或版主删除，多为推广。不过滤就会把垃圾当成用户声音。按 Reddit 条款，已删除内容也不该继续使用。
5. **第三方免费归档在收紧。** PullPush 已对 agent 返回 429 并要求付费；Arctic Shift 也会提示 “slow down”。不能把它们当作稳定的生产依赖。
6. **pytrends 已死。** 仓库已归档，核心接口 429/404。网上旧教程基本不可用。
7. **Google Trends 数值是相对值（0–100），不同请求之间不能直接比较。** 每次请求按该次窗口内的最高点归一化，而且网页版数据是抽样的。官方 API alpha 才提供跨请求一致的缩放。
8. **时间粒度随窗口变化。** 7 天是小时级，12 个月是周级，5 年是月级。拼接不同窗口会出错。
9. **TikTok 的数据全在签名的前端接口里。** 想拿就得逆向 `X-Bogus` / `msToken` 等签名，维护成本高，而且违反条款。
10. **TikTok Research API 不对商业开放。** 只对美国、欧洲、英国、加拿大、瑞士（以及巴西特定课题）的学术和非营利机构开放，要求“独立于商业利益”，审批约 4 周。
11. **代理本身也会不稳定。** 实测多次 SSL_ERROR_SYSCALL、读超时，所以要做重试和断点续抓，并且记录每次失败。

## 四、“不要做”原则

### 合规与账号安全
1. **不要绕过登录墙、验证码或签名机制**（例如逆向 TikTok 签名，或用机房代理池轮换绕过 Reddit 403）。
2. **不要把非商业授权的数据用在商业产品里。** Reddit 免费 API 和 Public Content Policy 明确写了商业用途要单独谈授权；TikTok Research API 只给学术用途。调研阶段内部看可以，但写进产品、卖给客户之前要先拿到授权。
3. **不要用个人主账号的 cookie 去抓。** 一旦被风控，封的是你本人的账号。
4. **不要伪造或冒用 User-Agent。** Reddit 要求格式为 `<platform>:<app ID>:<version> (by /u/<username>)`，伪装 UA 本身就违规。
5. **不要保存、展示或分析已删除的内容。** 定期按 ID 回查，删掉已删除的帖子和评论。
6. **不要采集超出调研需要的个人信息。** 只留文本、时间、版块、互动数；用户名做哈希，不抓头像、简介、私信。

### 抓取方法
7. **不要只看 HTTP 状态码判断成功。** 必须校验返回内容的结构和条数（见质量标准第 1 条）。
8. **不要无限速并发。** Reddit 官方上限是每个 OAuth client 100 次/分钟（按 10 分钟平均）；Google Trends 每次间隔至少 10–60 秒，碰到 429 要指数退避，而不是换 IP 硬冲。
9. **不要依赖单一免费第三方源**（PullPush、Arctic Shift、pytrends）。它们随时可能收紧，关键结论要能用第二个来源复现。
10. **不要在没有原始数据留档的情况下直接出结论。** 原始返回要按日期存档，保证结论可以回溯。

### 分析解读
11. **不要把 Reddit 点赞数/评论数当成需求规模。** 它只代表某个社区的活跃度，而且归档数据里的指标是早期快照。
12. **不要把多次 Google Trends 请求的数值直接拼接或比较。** 要比较就放在同一次请求里（最多 5 个词），或者用锚定词做归一化。
13. **不要把 TikTok 播放量当成购买意愿。** 只把它当作定性灵感。
14. **不要只从一个社区得出结论。** r/SaaS 里大多是创业者自己，不代表终端用户。

## 五、数据质量标准

每批数据入库前逐项检查，不达标就打回或标注。

### A. 采集完整性（每次请求都要检查）
| 检查项 | 标准 |
|---|---|
| 返回结构 | 能解析成预期 JSON，并且关键字段（id、时间、正文）都在。空 body、HTML 拦截页、`error` 字段都算失败 |
| 条数 | 实际条数 ≥ 请求条数的 90%，或者有分页结束标记；否则记为“部分失败” |
| 失败率 | 单批 429/403/超时 ≤ 5%；超过就暂停，不要硬重试 |
| 留档 | 每条记录都带 `source`、`fetched_at`、`query`、请求 URL，原始 JSON 单独保存 |

### B. 时效性
| 检查项 | 标准 |
|---|---|
| 指标成熟度 | 帖子要等发布 ≥ 72 小时、且最近一次抓取距发布 ≥ 48 小时，才能使用它的点赞/评论数；否则只用文本 |
| 新鲜度 | 调研结论用到的数据窗口要写清楚（例如 2026-07-01 至 2026-09-30）。超过 6 个月的数据单独标注 |
| Trends 窗口 | 记录 `time` 参数和粒度；粒度不同的序列不能拼接 |

### C. 真实性与去噪
| 检查项 | 标准 |
|---|---|
| 删除内容 | 剔除 `[removed]`、`[deleted]` 和 `removed_by_category` 非空的记录；剔除比例要写进报告（r/SaaS 实测约 40%） |
| 推广/机器人 | 标记带外链的、同一作者 24 小时内发 ≥ 3 帖的、账号很新的、文本高度重复（如相似度 > 0.9）的记录；它们在样本里占比要单独报告 |
| 去重 | 按平台原生 ID 去重；跨帖子按正文哈希去重 |

### D. 代表性
| 检查项 | 标准 |
|---|---|
| 来源分布 | 至少 3 个不同社区或渠道；任何一个来源占比不超过 50% |
| 样本量 | 定性主题归纳至少 200 条有效文本；需要给出比例的结论至少 400 条（约 ±5% 误差） |
| 人群偏差 | 报告里写明“谁在说话”（例如 Reddit 偏英语、偏男性、偏技术人群），不能推断成全体用户 |

### E. 可复现
| 检查项 | 标准 |
|---|---|
| 脚本 | 采集脚本、参数和版本存档；同样的参数重跑，结果条数偏差 ≤ 10% |
| 交叉验证 | 每个关键结论至少有两个独立来源支撑（例如 Reddit 痛点 + Trends 搜索量上升） |

## 六、建议的下一步（按优先级）

1. **申请 Reddit 官方 API**（几分钟）：在 reddit.com/prefs/apps 建一个 script 类型应用，用 PRAW 走 OAuth。调研阶段属于非商业用途，免费额度够用。这是最值得先做的一步。
2. **申请 Google Trends 官方 API alpha**（Search Central 申请表），同时小量需求先在网页手动导出 CSV。
3. **TikTok 先不要自己抓。** 先用 Creative Center 人工浏览热门话题；如果确实需要批量数据，再评估付费数据商，并确认对方的数据来源合规。
4. 定好调研的具体问题（目标用户、品类、竞品）之后，再按上面的质量标准搭一个最小采集管线。

## 一、改进清单（按价值排序）

| # | 改进 | 解决之前的什么问题 | 成本 |

## 二、各数据源的新路径

### Reddit
- **仍然首选官方 OAuth API**（非商业免费，100 次/分钟）。这一点没变。
- 新增备选：Academic Torrents 上的 Reddit 数据包，按版块下载，适合做历史基线（待核实覆盖时间）。
- 第三方实时 API（Redditapis 约 $0.002/次读取、FetchLayer、Xpoz 免费档等）出现了不少，但都是代抓，商业使用的授权问题不变，不建议作为主渠道。
- 商业授权价格：第三方文章说约 $0.24/千次调用、年最低约 $12,000（待核实）。等调研结论要进产品时再谈。

### Google Trends
- 官方 Trends API alpha（2025-07-24 发布）仍是唯一能跨请求一致缩放的渠道，**值得现在就去申请**。
- 第三方：SerpApi（免费 250 次/月）、DataForSEO（单次最多 5 个词，支持 Search/News/Images/Shopping/YouTube 五种来源）、Exploding Topics API（自有趋势数据，非 Google 原始值）。
- 没有官方 API 时的**拼接方法**见第三节。

### TikTok
- 新路径：**TikTok Shop 数据平台**（Kalodata 有 500 天历史、商品/达人/视频/直播维度；FastMoss 追踪 5000 万+商品）。如果调研的是电商品类，这比抓视频评论更直接。
- Commercial Content API 只给获批研究者，Creative Center 没有 API，这两条路不变。
- 视频和评论文本仍用 Apify 抓取器（已有文档）。

### 新增：YouTube、App Store、Amazon
- YouTube Data API v3：每天 10,000 单位免费配额。search 很贵（100 单位/次），评论列表便宜（1 单位/次）。建议用 Tavily 找视频 URL，省下 search 配额全用来拉评论。
- App Store：Apple 公开评论 RSS，适合 App 类竞品（每个 App 能拿到的条数有限，待核实）。
- Amazon：完整评论列表要登录，公开页只有评分分布和精选评论。需要时用 Apify 或 SerpApi，不要用个人账号。

## 三、Google Trends 拼接方法（锚定 + 重叠窗口）

适用于：要比较超过 5 个词，或要很长时间段的日级数据。

1. **选一个锚定词**：搜索量稳定、和目标词量级接近的词（例如品类大词）。每次请求都带上它，最多再加 4 个目标词。
2. **超过 5 个词**：分组请求，每组都含锚定词；用“目标词 ÷ 锚定词”换算到同一尺度。
3. **长时间段日级数据**：切成 ≤ 90 天的窗口（这个长度才返回日级），相邻窗口重叠约 15–30 天。
4. **每个窗口请求多次取平均**：Google 网页版数据是抽样的，同样参数不同时间请求会有波动。
5. **相邻窗口用重叠日的中位数比值做缩放**，链式换算回第一个窗口的尺度。
6. **最后用全时段周级数据校准**：单独请求整个时段的周级曲线，用它把拼好的日级序列整体缩放回 0–100。
7. **记录所有参数**（geo、时间、类别、请求时间），否则不可复现。

参考实现：GitHub 上的 `wan-huiyan/google-trends-browser-fetch`、`charlie-collard/rebuild_trends`（未测试，用前先读代码）。

## 四、新增质量标准（补充《爬取实测与数据原则》第五节）

### F. 样本量与饱和
| 检查项 | 标准 |
|---|---|
| 定性主题 | 在 200 条门槛之外，按批（每批 50 条）编码，**连续两批没有出现新主题**才算饱和；没饱和就继续采 |
| 比例结论 | 仍按 400 条（约 ±5%）；分群比较时每个群各需 ≥ 100 条 |

### G. LLM 辅助编码
| 检查项 | 标准 |
|---|---|
| 编码框架 | 编码前先写好框架：标签名、定义、正例、反例。常用维度：痛点类型、期望结果、提到的产品、情绪 |
| 一致性检验 | 随机抽 100 条，人工和 LLM 各自独立打标，算 Cohen's κ。**κ ≥ 0.70 才能放量**；0.60–0.70 修框架后重测；< 0.60 不用 LLM 结果 |
| 持续抽检 | 放量后每 500 条再抽 30 条人工复核 |
| 情感分析 | 人与人之间的情感判断一致率上限大约 80%，所以不要追求更高的“准确率”，而是报告 κ 和抽检结果 |

### H. 信号交叉验证
| 检查项 | 标准 |
|---|---|
| 三类信号 | 关键结论尽量覆盖用户原话、需求量级、市场行为中的至少两类 |
| 方向一致 | 如果社区里吐槽多但搜索趋势在下降，要在报告里写出矛盾，不能只挑支持的证据 |

### I. 去重与机器人（细化 C 项）
| 检查项 | 标准 |
|---|---|
| 近似重复 | 除原生 ID 和正文哈希外，用文本相似度（例如 MinHash 或向量相似度 > 0.9）去掉换几个字的转帖 |
| 机器人特征 | 发帖间隔高度规律、多账号相同内容、短时间极高频、内容和主题无关，满足任两条就标记 |

## 五、Tavily 用法优化

- **先 /map 后 /extract**：/map 只返回 URL 列表，先筛再抽取，比直接 /crawl 省 credits。
- **search_depth**：发现阶段用 basic（1 credit），只在需要高质量摘要时用 advanced（2 credits）。
- **限定域名**：用 include_domains 把 Reddit、YouTube、行业媒体分开搜，结果更集中。
- **Exa 做补充**：要找“和这篇类似的讨论”时，Exa 的语义搜索更合适；Tavily 仍做默认。
- **用量**：本次 12 次 advanced 搜索约 24 credits。每月 1000 credits 够做约 30–40 轮这样的调研。

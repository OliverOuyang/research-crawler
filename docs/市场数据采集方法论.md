# 市场数据采集方法论：怎么高效、全面地拿数据

> 调研时间：2026-10-09。来源是 12 次 Tavily advanced 搜索（每次 6–8 个结果）的摘要和结果列表，文末列出主要链接。价格和配额来自第三方文章，付费或申请前以官网为准。标“待核实”的数字只在一个来源里出现过。

## 一、一句话结论

**先定问题，再按“三类信号 × 两层工具”组合采集，最后用同一套质量标准验收。** 三类信号是：用户原话（社区、评论）、需求量级（搜索趋势）、市场行为（销量、广告、价格）。两层工具是：发现层（Tavily 这类搜索 API，找到该抓哪里）和结构化层（官方 API 或按条计费的抓取器，拿可量化字段）。任何结论至少要两类信号互相印证。

## 二、流程（五步）

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 1. 定问题 | 写清目标用户、品类、竞品、要回答的 3–5 个问题、时间窗口 | 调研简报 + 关键词表（含同义词、竞品名、痛点词） |
| 2. 发现 | 用 Tavily /search、/map 找相关社区、帖子、评测、竞品页面；Google Trends 网页先看大方向 | 来源清单（每条带 URL、平台、为什么相关） |
| 3. 结构化采集 | 按下面第三节选渠道，先跑 20–50 条小样本人工核对，再放量 | 原始数据按日期存档 + 清洗后的表 |
| 4. 清洗与编码 | 去重、去删除内容、标记推广和机器人；建编码框架（痛点类型、期望结果、提到的产品），LLM 辅助打标并抽检 | 带标签的文本表 + 剔除比例 |
| 5. 交叉验证与输出 | 社区痛点 × 搜索趋势 × 市场行为互相对照；写清“谁在说话”和数据窗口 | 结论 + 证据链接 + 局限说明 |

采集节奏：一次性调研按上面走一遍；持续监控按日或按周增量抓取，只抓新内容和需要更新指标的旧内容。

## 四、工具选择

| 场景 | 首选 | 说明 |
|---|---|---|
| 发现和读网页 | **Tavily**（已接入，每月 1000 credits） | 搜索、抽取、站点地图、爬取一体；先 /map 找 URL 再 /extract，避免 /crawl 一次花太多 credits |
| 语义找相似内容 | Exa | 按意思找“类似这篇”的页面，Tavily 找不全时补充 |
| 平台结构化数据 | 官方 API > Apify 按条计费抓取器 | Apify 热门 Reddit/TikTok/Trends 抓取器 $0.3–4/千条，详见已有文档 |
| 通用网页转 Markdown | Firecrawl（托管，约 $16/月 5k credits）或 Crawl4AI（开源自托管） | 抓竞品站、帮助中心、定价页 |
| 难抓的站 | Bright Data | 反爬成功率最高但贵，调研阶段一般用不上 |
| 自写爬虫 | Scrapy（静态页）+ Playwright（JS 页面） | 只在没有现成 API 或抓取器时用；要自己处理代理和限速 |
| 文本分析 | MiniMax（已接入）或 Claude | 打标、聚类、摘要；必须抽检，见《改进路径与标准》第四节 |

## 五、效率要点

1. **发现和采集分开。** 先用便宜的搜索确定“抓哪里”，再对选中的来源做结构化采集，不要一开始就全量爬。
2. **小样本先行。** 每个新渠道先跑 20–50 条，人工核对字段和条数，再放量。
3. **增量而不是重抓。** 记录每个来源的最后抓取时间和 ID，只抓新增；指标需要成熟（发布 ≥ 72 小时）再回抓一次。
4. **按条计费优先。** 调研量级下，按条计费的抓取器比按算力或订阅便宜。
5. **原始数据先落盘。** 原始返回按日期存档，清洗和分析都从存档读，出错能回溯、不用重抓。
6. **配额预算。** 每轮调研前估算 Tavily credits、YouTube 配额、Apify 费用，见《抓取平台选型与组合》第四节。
